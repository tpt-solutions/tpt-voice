# tpt-voice

**A pure-Rust, memory-safe speech processing engine. Transcription, voice isolation, diarization, and text-based editing. The intelligence layer of the TPT AV stack.**

**License:** MIT OR Apache-2.0  
**Status:** Early-stage / Pre-1.0  
**Ecosystem:** [TPT Solutions Open Source](https://opensource.tptsolutions.co.nz/)

---

## 1. Vision & Philosophy

`tpt-voice` is the **speech and AI layer** of the TPT AV Stack. It provides pure-Rust implementations of speech recognition, voice separation, speaker identification, and text-based editing workflows.

The current Rust ecosystem has **zero pure-Rust speech processing libraries**. Every existing solution (`whisper-rs`, `vosk`, `deepspeech`) is a binding to C/C++ code, which means:
- GPL/LGPL licensing contamination
- Complex build systems and cross-compilation nightmares
- No real-time safety guarantees
- No integration with Rust's type system and memory safety

`tpt-voice` fills this gap by providing:
1. **Pure Rust ASR** (Automatic Speech Recognition) — no C/C++ dependencies
2. **Real-time voice isolation** — AI-driven noise reduction tuned for human speech
3. **Speaker diarization** — identifying "Speaker A" vs "Speaker B" in multi-person recordings
4. **Text-based editing** — the ability to edit audio/video by editing a transcript
5. **Permissive licensing only** — dual MIT OR Apache-2.0; zero copyleft contamination

### Core Tenets

1. **Pure Rust, Zero External AI Dependencies:** No PyTorch, no TensorFlow, no C/C++ bindings. All models are implemented in pure Rust or use permissively licensed Rust ML crates.
2. **Real-Time Capable:** Voice isolation and transcription can run in real-time or faster-than-real-time on modern hardware.
3. **Streaming-First Architecture:** All processing supports streaming input (audio chunks) rather than requiring the entire file upfront.
4. **Text-Based Editing Native:** The engine is designed from the ground up to support editing audio/video by manipulating text transcripts.
5. **Pure Permissive Licensing:** MIT OR Apache-2.0 only. No GPL/LGPL/MPL dependencies. Enforced via `cargo-deny` in CI.
6. **Composable Architecture:** Each sub-crate is independently useful. A developer can use just the transcriber, just the voice isolator, or just the diarizer.

## 2. Ecosystem Integration

`tpt-voice` sits in the **Intelligence Layer** of the TPT AV Stack, consuming decoded audio from `tpt-audio` and providing semantic understanding (text, speaker labels, isolated voices).

| Crate | Role | Relationship to `tpt-voice` |
| :--- | :--- | :--- |
| **`tpt-cadence`** | Audio codecs | Decodes audio files into raw PCM `f32` samples. `tpt-voice` consumes this PCM. |
| **`tpt-audio`** | Audio processing, timeline | Manages the audio timeline. `tpt-voice` provides transcript data that can be linked to timeline clips. |
| **`tpt-voice`** | **Speech & AI (this repo)** | Transcribes audio, isolates voices, identifies speakers, and enables text-based editing. |
| **`tpt-visual`** | Video processing | Can consume transcript data for auto-captioning and subtitle generation. |

### Data Flow
tpt-cadence (decodes audio files → raw PCM f32)
↓
tpt-audio (manages timeline, plays audio)
↓
tpt-voice (processes PCM → transcript, speaker labels, isolated voices)
↓
Application (displays transcript, enables text-based editing, generates captions)

/// A complete transcript of an audio file.
pub struct Transcript {

    /// Full text (concatenation of all segments).

    /// Language code (e.g., "en", "es", "fr").

    /// Confidence score (0.0 to 1.0).

}

/// A single segment of the transcript (sentence or phrase).

    pub id: SegmentId,
    /// Start time (in seconds).
    pub start_time: f64,
    /// End time (in seconds).
    pub end_time: f64,
    /// Text content of the segment.

    /// Speaker label (if diarization was performed).
    pub speaker: Option<SpeakerLabel>,
    /// Confidence score for this segment.
    pub confidence: f32,
    /// Word-level timestamps (optional).
    pub words: Option<Vec<WordTimestamp>>,
}

/// Word-level timestamp.
pub struct WordTimestamp {
    /// The word.
    pub word: String,
    /// Start time (in seconds).
    pub start_time: f64,
    /// End time (in seconds).
    pub end_time: f64,
    /// Confidence score.
    pub confidence: f32,
}

/// Speaker label.
pub struct SpeakerLabel {
    /// Speaker identifier (e.g., "SPEAKER_00", "SPEAKER_01").
    pub id: String,
    /// Display name (if known).
    pub name: Option<String>,
}

5. Model Architecture
5.1. ASR Model (Transcription)
tpt-voice implements a transformer-based encoder-decoder architecture similar to Whisper, but written entirely in pure Rust.
Encoder:
Input: Mel spectrogram (80 or 128 channels)
Architecture: Transformer encoder (12-24 layers)
Output: Audio embeddings
Decoder:
Input: Audio embeddings + text tokens (autoregressive)
Architecture: Transformer decoder (12-24 layers)
Output: Text token probabilities
Training:
Models are pre-trained on large datasets (LibriSpeech, Common Voice, etc.)
Weights are stored in a custom binary format (or safetensors)
No PyTorch/TensorFlow runtime required
5.2. Voice Isolation Model
Architecture: U-Net or transformer-based time-frequency masking
Pipeline:
Input audio → STFT (magnitude + phase)
STFT → Separation model (predicts masks for voice/noise)
Apply masks → Inverse STFT → Isolated audio
5.3. Speaker Embedding Model
Architecture: Time-delay neural network (TDNN) or ECAPA-TDNN
Pipeline:
Input audio → Feature extraction (MFCC or mel spectrogram)
Features → Embedding model → Fixed-size speaker embedding (256 or 512 dimensions)
Embeddings → Clustering (spectral clustering or agglomerative hierarchical clustering)
6. Performance Considerations
6.1. Real-Time Factor (RTF)
Task
Target RTF
Hardware Requirement
Transcription
< 0.5x (2x faster than real-time)
CPU (AVX2) or GPU
Voice Isolation
< 1.0x (real-time)
CPU (AVX2) or GPU
Diarization
< 0.3x (3x faster than real-time)
CPU
6.2. SIMD Optimization
All heavy numerical operations (matrix multiplication, FFT, convolution) use SIMD intrinsics:
x86_64: AVX2, AVX-512 (via std::arch)
ARM: NEON (via std::arch)
Fallback: Pure Rust scalar code
6.3. GPU Acceleration (Optional)
For maximum performance, tpt-voice can optionally use wgpu for GPU-accelerated inference:
Transformer attention: GPU matrix multiplication
STFT/ISTFT: GPU FFT
Convolution: GPU convolution
